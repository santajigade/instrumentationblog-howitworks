How Modbus RTU Communication Works

Change the baud rate, the slave address and the number of holding registers read. Watch the request and reply frames travel on the RS 485 line, the CRC bytes recalculate and the frame times change.

Live animationAdjustable slidersFormula and example

Quick answer: Modbus RTU is a master and slave protocol on a serial line, usually RS 485. The master sends a frame with the slave address, a function code, data and a CRC; only the addressed slave answers, and frames are separated by a silent gap of at least 3.5 character times.

What Is a Modbus RTU Communication?

Modbus RTU is one of the most common field protocols for energy meters, VFDs, flow computers, analysers and small PLCs. It runs on a two wire RS 485 line that can carry up to 32 unit loads per segment.

Only the master starts a transaction. Each slave has an address from 1 to 247, listens to every frame on the line and replies only when the address matches.

A frame has no start or end character. The receiver finds the frame boundaries from silent gaps on the line and checks every frame with a 16 bit CRC.

Modbus RTU Communication Working Principle Step by Step

  1. The master waits for a silent line of at least 3.5 character times, then sends the slave address, function code, start register, quantity and CRC.
  2. Every slave receives the frame and checks the CRC; a frame with a wrong CRC is ignored.
  3. Only the slave whose address matches executes the request and reads the holding registers.
  4. After a silent gap, the slave replies with its address, the function code, a byte count, the register data and a new CRC.
  5. The master checks the CRC of the reply, stores the values and moves on to the next request after another silent gap.

Modbus RTU Communication Formula

Character time = 11 bits ÷ baud rate (1 start, 8 data, 1 parity, 1 stop, or 2 stop bits without parity)
Function 03 request = 8 bytes; reply = 5 + 2 × N bytes for N registers
Silent gap t3.5 = 3.5 × character time; above 19200 bit/s it is fixed at 1.75 ms
Transaction time = (8 + 5 + 2 × N) × character time + 2 × t3.5, not counting slave processing time
Example: 9600 bit/s, slave 17, N 3, start register 006B hex: character 1.146 ms, request 11 03 00 6B 00 03 76 87 = 9.17 ms, reply 11 bytes = 12.60 ms, t3.5 = 4.01 ms, total = 19 × 1.146 + 2 × 4.01 = 29.79 ms

MasterStarts every transaction and handles timeouts and retries

RS 485 transceiversDrive the differential A and B lines and switch between send and receive
Termination resistorsAbout 120 Ω at each end of the trunk to stop reflections
CRC 16Two check bytes, low byte first, calculated over the whole frame

Where a Modbus RTU Communication Is Used

Energy metersA PLC or SCADA reads voltage, current and energy registers.
DrivesSpeed reference, run command and fault codes over one cable.
Package unitsCompressor, chiller and analyser panels report data to the DCS.
Remote I/O and RTUsLow cost serial links to small outstations.

Advantages

  • Simple, open and supported by almost every controller
  • Needs only a twisted pair over long distances
  • Easy to diagnose with a serial sniffer

Limitations

  • Slow compared with Ethernet; one master asks one slave at a time
  • No built in data types, so word order and scaling must be agreed
  • A single bad device or wrong termination can upset the whole line

Modbus RTU Communication Field Tips and Common Problems

  • Set the same baud rate, parity and stop bits on the master and every slave; one mismatch gives CRC errors or silence.
  • Use shielded twisted pair, a daisy chain topology and termination only at the two ends of the trunk.
  • Check the register map for the offset: register 40108 in a manual is often address 006B hex in the frame.
  • Set the master timeout longer than the slave response time, and keep retries low so one dead slave does not slow the whole poll cycle.

Frequently Asked Questions

Why is the CRC sent low byte first?

The Modbus serial specification sends the CRC low order byte first. In the example the CRC is 8776 hex and the frame ends with 76 87.

What is the 3.5 character gap for?

RTU frames have no start or end marker. A silent time of at least 3.5 characters tells every device that one frame has ended and the next can start.

How many devices can be on one Modbus RTU line?

Addresses run from 1 to 247, but one RS 485 segment carries 32 unit loads. More devices need repeaters or low load transceivers.

What is the difference between Modbus RTU and Modbus TCP?

RTU uses binary frames with a CRC on a serial line. TCP wraps the same function codes in an Ethernet packet with an MBAP header and no CRC.
