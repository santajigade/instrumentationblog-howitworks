How SCADA Polling Works

Change the number of RTUs, the baud rate and the registers read in each poll. Watch the master question each RTU in turn and see how long one full poll cycle takes.

Live animationAdjustable slidersFormula and example

Quick answer: In a polled SCADA system the master station sends a request to one RTU, waits for its reply, then moves to the next RTU. The time for one full round of all RTUs is the poll cycle, and it sets how fresh the data on the operator screen can be.

What Is a SCADA Polling System?

Most serial SCADA networks work on a master and slave basis. Field RTUs never talk on their own; they answer only when the master asks, so only one device uses the line at any time.

Each poll costs time on the wire: the request frame, the RTU processing delay and the reply frame. On a slow serial link these add up quickly as RTUs and registers are added.

Knowing how to estimate the poll cycle helps when you size a telemetry network, choose a baud rate or explain to operations why a value on the screen is a few seconds old.

SCADA Polling System Working Principle Step by Step

  1. The master builds a request for one RTU with its address, the function code, the first register and the number of registers.
  2. The request travels over the shared line; every RTU hears it, but only the addressed RTU acts on it.
  3. The RTU reads its data, waits its turnaround time and sends a reply frame with the register values and a CRC.
  4. The master checks the CRC, updates its database and moves on to the next RTU, or retries after a timeout if no reply came.
  5. When the last RTU is done the cycle starts again; the time for one round is the poll cycle seen as data refresh on the screens.

SCADA Polling System Formula

Poll time per RTU = (request bytes + reply bytes + 7 gap characters) × 11 bits ÷ baud rate + RTU reply delay
Modbus RTU style frames: request 8 bytes; reply 5 + 2 × registers bytes; each character is 11 bits on the line
Full poll cycle = number of RTUs × poll time per RTU
This demo assumes a fixed RTU reply delay of 20 ms and no retries
Example: 20 registers at 9600 baud: (8 + 45 + 7) × 11 ÷ 9600 = 68.8 ms, plus 20 ms = 88.8 ms; 8 RTUs need about 0.71 s

RTUField unit that reads local I/O and answers only when it is addressed

Where a SCADA Polling System Is Used

Pipeline and water networksPolls pumping stations, valve stations and tanks spread over long distances.
Power distributionReads breaker status and feeder measurements from substation RTUs.
Oil and gas wellheadsCollects flow, pressure and alarm data from remote well sites.
Network sizingEstimates whether a baud rate and number of RTUs give the refresh time operations need.

Advantages

  • Simple, deterministic access: only one device talks at a time
  • Easy to detect a failed RTU from missing replies
  • Works on low bandwidth serial and radio links

Limitations

  • Poll cycle grows with every RTU and register added
  • A silent RTU wastes a full timeout on every cycle
  • Events between polls are only seen at the next poll unless the RTU time stamps them

SCADA Polling System Field Tips and Common Problems

  • Read registers in one block per RTU instead of many small requests; frame overhead is paid per request.
  • Set the timeout just above the real reply time; a long timeout on a dead RTU slows the whole channel.
  • Poll alarm and status data more often than slow values such as totals or diagnostics.
  • Check baud rate, parity and stop bits on both ends first when an RTU gives CRC errors or no reply.

Frequently Asked Questions

What is a poll cycle in SCADA?

It is the time the master takes to request and receive data from every RTU on a channel once. A value on the screen can be up to one poll cycle old.

Why is each character 11 bits?

A Modbus RTU character has 1 start bit, 8 data bits, 1 parity bit and 1 stop bit, or 2 stop bits when parity is not used.

How can I make SCADA polling faster?

Raise the baud rate if the line allows, read data in larger blocks, remove unused registers, split RTUs over more channels and shorten timeouts.

What is the difference between polling and report by exception?

In polling the master asks every RTU every cycle. In report by exception an RTU sends data only when a value changes beyond a deadband, which saves bandwidth.
