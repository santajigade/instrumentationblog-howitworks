How SCADA Report by Exception Works

Set the analog deadband, the size of the process swing and the poll interval you would otherwise use. Watch the RTU send a message only when the value moves past the deadband and compare the traffic with plain polling.

Live animationAdjustable slidersFormula and example

Quick answer: In report by exception the outstation or RTU sends a value to the SCADA master only when it has changed by more than a set deadband, or when a digital point changes state. Quiet points send nothing, so the link carries far fewer messages than when the master polls every point on a fixed cycle.

What Is a SCADA Report by Exception?

Classic SCADA polling asks every outstation for every point on a fixed cycle, even when nothing has changed. On slow radio, satellite or leased line links that wastes most of the bandwidth and delays the messages that matter.

Report by exception turns this around: the outstation watches its own points and creates an event only when a digital input changes or an analog value moves by more than its deadband. Protocols such as DNP3 and IEC 60870 5 101 and 104 support this, with events stored in a buffer and sent with a time stamp.

The events reach the master either as unsolicited responses or when the master polls for event data. A slower integrity poll of all static values still runs in the background so the master database cannot drift out of step.

SCADA Report by Exception Working Principle Step by Step

  1. The RTU scans its inputs and keeps, for each analog point, the last value it reported to the master.
  2. On every scan it compares the new value with that last reported value.
  3. When the difference reaches the deadband, or a digital input changes state, the RTU creates an event with the value and a time stamp and puts it in the event buffer.
  4. The RTU sends the buffered events to the master as an unsolicited response, or the master collects them in its next event poll, and the master confirms receipt.
  5. The master updates its database and trends; a periodic integrity poll of all static values keeps the database aligned if any event was lost.

SCADA Report by Exception Formula

Report when |PV − last reported value| ≥ deadband
The value at the master is never more than one deadband away from the real value
For a sine swing of peak A: total travel per cycle = 4 × A, so reports per cycle ≈ 4 × A ÷ deadband
Polling sends one response per point every poll interval, changed or not
Example: A 10 %, deadband 2 %, one cycle per minute: 4 × 10 ÷ 2 = 20 reports per minute, against 60 ÷ 2 s = 30 polled responses, so about 33 % fewer messages

Where a SCADA Report by Exception Is Used

PipelinesPressure and flow stations along a pipeline report changes over narrow radio or satellite links.
Water networksReservoir levels and pump status from many remote sites reach the control room without constant polling.
Electrical substationsBreaker trips and alarms are sent at once with time stamps for the sequence of events record.
Oil and gas wellheadsSolar powered RTUs save energy and airtime by staying quiet when nothing changes.

Advantages

  • Much less traffic when values are steady
  • Changes and alarms arrive quickly instead of waiting for the next poll
  • Events carry time stamps, which keeps the true order of fast changes

Limitations

  • A deadband set too wide hides real changes from operators
  • A deadband set too narrow on a noisy signal floods the link
  • Needs an integrity poll and event buffering to recover from lost messages

SCADA Report by Exception Field Tips and Common Problems

  • Set analog deadbands per point from the process need, often around 1 to 2 % of span, and widen them on noisy signals.
  • Keep an integrity poll running, for example every few minutes to an hour, so a lost event cannot leave a stale value on the screen.
  • Check that the RTU clock is synchronised, otherwise event time stamps from different sites cannot be compared.
  • Watch the event buffer size; if it overflows during a long link outage the oldest events are lost.

Frequently Asked Questions

What is the difference between polling and report by exception?

With polling the master asks for every point on a fixed cycle. With report by exception the outstation sends a value only when it changes by more than the deadband.

What is an unsolicited response in DNP3?

It is a message the outstation sends without being asked, carrying new event data. The master answers with a confirmation so the outstation can clear those events from its buffer.

Why is an integrity poll still needed?

Events can be lost through a buffer overflow, a restart or a link fault. The integrity poll reads all current values so the master database is correct again.

How do I choose the analog deadband?

Pick the smallest change the operator or historian really needs to see, then check the traffic. A noisy signal needs a wider deadband or some filtering in the RTU.
