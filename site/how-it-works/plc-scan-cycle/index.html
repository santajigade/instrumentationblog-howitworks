How a PLC Scan Cycle Works

Change the scan time and the length of the sensor pulse. Watch the PLC read its inputs once per scan and see when a short pulse slips through unseen.

Live animationAdjustable slidersFormula and example

Quick answer: A PLC works in a repeating loop called the scan cycle. It copies all inputs into memory, runs the program from top to bottom using that copy, then writes the results to the outputs, and starts again.

What Is a PLC Scan Cycle?

Every PLC, from a small brick to a large rack system, runs its program in a continuous loop. One pass of that loop is called a scan, and the time it takes is the scan time, usually a few milliseconds to a few tens of milliseconds.

Inside a scan the PLC does not look at the real input terminals while the program runs. It works from an input image taken at the start of the scan, and the outputs only change when the output image is written at the end.

This simple idea explains many field problems: slow response, missed short pulses from sensors and outputs that seem to flicker. Understanding the scan cycle is the first step in troubleshooting PLC logic.

PLC Scan Cycle Working Principle Step by Step

  1. Input scan: the PLC reads every input terminal and stores the states in the input image table.
  2. Program scan: it executes the program rung by rung, using only the input image, and writes results to the output image.
  3. Output scan: the output image is copied to the physical output terminals.
  4. Housekeeping: communication, diagnostics and the watchdog timer are serviced.
  5. The cycle repeats immediately, so a typical PLC completes hundreds of scans every second.

PLC Scan Cycle Formula

Scan time = input read + program execution + output write + housekeeping
Scans per second = 1000 ÷ scan time (ms)
Worst case response ≈ 2 × scan time + input filter + output delay
A pulse is only guaranteed to be seen if it lasts longer than one scan
Example: 20 ms scan gives 50 scans per second and up to about 40 ms response

Main Parts of a PLC Scan Cycle

PartWhat it does
Input moduleConverts field signals (24 V DC, 230 V AC) to logic levels, often with a filter delay
Input image tableMemory copy of all inputs taken at the start of each scan
CPU and programExecutes the user program using the image tables
Output image tableMemory where the program writes output results
Watchdog timerStops the PLC if one scan takes longer than the set limit

Where a PLC Scan Cycle Is Used

Troubleshooting slow responseExplains delays between a sensor change and an output action.
Fast pulsesShows when to use high speed counters or interrupt inputs instead of normal inputs.
Program designHelps place logic in the right order so a result is used in the same scan.
System sizingGuides the choice of CPU when the program grows or loops get faster.

Advantages

  • Predictable, repeatable execution of logic
  • Inputs stay stable during one scan, so logic is consistent
  • Easy to measure and monitor scan time in the CPU diagnostics

Limitations

  • Short pulses can be missed if they fall between input reads
  • Response time grows as the program grows
  • Very long programs can trip the watchdog timer

PLC Scan Cycle Field Tips and Common Problems

  • Check the scan time in the CPU diagnostics before blaming a sensor for slow response.
  • Use a high speed counter or interrupt input for pulses shorter than the scan time.
  • Do not use loops that wait for an input inside the program; the input image will not change during the scan.
  • Remember the input filter time adds to the response; reduce it only if noise allows.

Frequently Asked Questions

What is a typical PLC scan time?

Small programs often run in 1 to 10 ms and large programs in 20 to 100 ms. The CPU shows the actual, minimum and maximum scan time in its diagnostics.

Why can a PLC miss a short pulse?

Inputs are read only once per scan. If a pulse starts and ends between two reads, the program never sees it.

What is the watchdog timer?

It is a timer that stops the PLC and sets outputs to a safe state if a scan takes too long, for example because of an endless loop.

Does the order of rungs matter?

Yes. A result calculated in a later rung is only used by earlier rungs in the next scan, which can add one scan of delay.
